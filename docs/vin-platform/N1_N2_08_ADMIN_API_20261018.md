# N1 → N2-08: admin read/write contract

Version `vin-platform-1` (additive). Upgrade **0024_vin_admin_revisions** before running this code; default feature flag stays off. Existing write bodies are unchanged. All routes require current PLATFORM_ADMIN in administration workspace, same tenant; no caller-granted catalog shortcut.

| Read | Filters | Revision |
| --- | --- | --- |
| GET /admin/vin/quota-policies | subject, subject_kind=user/group/role/pool, active | subject + revision; policy contains the complete replacement body |
| GET /admin/vin/catalog | kind, environment, active | catalog_id + version; includes inactive and resources not granted to the caller |
| GET /admin/vin/grants | catalog_id, subject_kind, subject_id, active | id + revision |
| GET /admin/vin/memberships | user_id, group_id, active | id + revision |
| GET /admin/vin/accounts | user_id, eligible | user_id + revision; missing eligibility is false/revision 0 |
| GET /admin/vin/catalog/{catalog_id}/documents | review_status=candidate/approved/retired | document_id + opaque revision (64 hex); no text/blob URI/secret |

Every list accepts offset >= 0 and limit 1..100 (default 25); returns items/total/offset/limit/next_offset/contract_version. Stable sort is subject for policies, user_id for accounts, id for other lists. Continue at next_offset, stop at null. Lists are live views, not a multi-page snapshot.

PUT quota-policies/{subject}, PUT accounts/{user_id}/eligibility and DELETE grants/{id}, memberships/{id} accept query `expected_revision`. A stale revision returns 409 REVISION_CONFLICT; reload before editing. Omitted revision preserves existing N2 compatibility. For a new quota policy use 0; policy response returns updated/revision. Catalog POST retains its existing monotonically increasing `version` contract.

DELETE /admin/vin/quota-policies/{subject}?expected_revision=N removes an override from policy selection, retaining the row/audit and incrementing revision. Thus a user can fall back to a group/role policy without losing quota usage or reusing an old revision. To restore, PUT using the current revision from the inactive row. A policy with active=true and enabled=false denies execution; an inactive override falls back. Do not confuse those states.

POST /admin/vin/catalog/{catalog_id}/documents/{document_id}/review accepts `{status:"approved"|"retired",expected_revision:"<read token>"}` and returns updated safe document metadata. Approval requires lifecycle ready. CAS rejects content/lifecycle/review changes since read, on SQL and Redis. Only documents in a catalogued Vin library in the same tenant can be reviewed; this is not a private-customer-document listing API. Replays with an old token return 409 and must reload. Retrieval already checks approved status on each use, including cached results.
